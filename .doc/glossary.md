# Glossary

| Term | Meaning | Preferred usage |
| --- | --- | --- |
| API key | Credential presented in `x-api-key` to authenticate a gateway caller. | Do not call it a token or secret once referring to the stored record. |
| AI-agent activity record | A factual `PROMPTS.md` entry for one agent run, including observed prompt, timing, outcome, and workspace changes. | Use this phrase for development-process traceability, not gateway audit logging. |
| Agent run | One bounded execution by an AI agent or tool in response to a user prompt. | Record the observed agent/tool identity and outcome. |
| API-key ID | Non-secret, immutable identifier for an API key record. | Use `apiKeyId` in code, audits, and Redis keys; never log raw API keys. |
| Audit log | Minimal MongoDB record of a gateway request outcome and security metadata. | Use `audit log`, not request log; it excludes raw content. |
| Blocked | A request or provider response that the gateway refuses due to a security control. | Audit status: `blocked`. |
| Challenge corpus | The attack and PII examples referred to as Appendix A in the challenge brief. | Treat as untrusted test data. The supplied PDF does not currently include it. |
| Correlation ID | A per-request identifier used to associate logs, errors, and audits. | Use `correlationId`. |
| Detokenisation | Restoring an original PII value from an opaque token. | Must be explicit, access-controlled, encrypted, and audited. |
| Gateway | This SecureLLM Gateway service. | Use `gateway` for the service; do not conflate it with a provider. |
| Injection echo | Provider output that repeats a detected inbound injection payload or its normalised equivalent. | Treat as unsafe outbound output. |
| LLM provider | The external model service selected at runtime, initially OpenAI or Anthropic. | Use `provider` in code; name the concrete vendor only in adapters/configuration. |
| PII | Personally identifiable information. | In scope: email, phone number, and Israeli national ID. |
| PII token | Opaque replacement for a detected PII value, such as `[PII:email:<random>]`. | Tokens must be non-meaningful and request-scoped. |
| Prompt injection | Malicious or untrusted content attempting to override instructions, exfiltrate hidden context, or spoof control delimiters. | Use typed `ThreatCode` values rather than a Boolean-only result. |
| Prompt record | The user prompt preserved in an AI-agent activity record. | Preserve verbatim except for secret, credential, or production-data redaction. |
| Provider output | Text generated by the LLM provider. | Always describe it as untrusted until outbound validation succeeds. |
| Rate-limit window | The rolling 60-second period used to count requests per API-key ID. | Use `sliding window`, not fixed window. |
| Redaction | Replacing detected PII with a PII token before sending content to the provider. | Use `redaction` for the request transformation; do not imply deletion from a token vault. |
| Secret-shaped value | Output matching a risky credential pattern, including OpenAI-style keys, JWTs, or AWS access-key IDs. | Use this term in threat codes and documentation; do not print matched values. |
| Threat code | Stable typed identifier describing a detected security condition. | Use `ThreatCode`; avoid putting prompt content in reason fields. |
| Token vault | Separate, protected storage for reversible PII mappings when that capability is implemented. | It is not the audit log and must have encryption, access control, expiry, and auditing. |
| Worktree snapshot | Version-control state captured before or after an agent run to determine file changes. | Use repository-relative paths; do not rely on an agent's self-reported change list. |
